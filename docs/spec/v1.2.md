# v1.2：每一列都能點開詳細（spec）

來源：Brian（經 Kazuha 2026-10-09）。**推翻 v1.1「歷史列不連到詳情」**（decisions.md 加第 25 條）。

## 範圍
首頁「最近紀錄」與「紀錄」頁的每一列都可以點，打開那筆的詳細頁。

| 類型 | 點了去哪 |
|---|---|
| 異常（Issue） | 現有 `#issue/<id>` 異常詳情 |
| 餵食 Feed、清砂 Litter、體重 Weight、驅蟲／疫苗／用藥 Med、居家維護 Care | 新的共用詳細頁 `#entry/<table>/<id>` |

## 共用詳細頁 EntryDetail
- 標題：類型名（例「副食／零食」「清砂」「體重」「驅蟲／疫苗／用藥」「居家維護」），返回鍵回到來源（首頁或紀錄頁，保留紀錄頁的捲動位置與篩選）。
- 內容：一張資訊卡，列出這筆的所有欄位，用現有 `describe.ts` 的繁中文字；空白欄位不顯示（不要出現「三合一疫苗：」這種半截字，順便修掉 backlog 這條）。共同欄位：時間（含年份，若不是今年）、記錄人、備註。
- 有照片的（Litter photo_ids）沿用 v1.1.1 的 PhotoThumb／PhotoViewer。
- 底部動作：「編輯」打開現有 `EditEntrySheet`；「撤銷」沿用現有軟刪除與「復原」toast。已撤銷的列：詳細頁顯示「已撤銷」badge，動作只剩「復原」。
- 找不到該筆（例如還沒載到、id 錯）：顯示「找不到這筆紀錄」與「回紀錄頁」。從 history 載入的舊列也要能打開（從已載入的資料找）。
- 待送（__pending）列也能打開，顯示現有的待送標示，編輯／撤銷照現有離線佇列行為。

## 列的互動
- 依 DESIGN.md v0.6 §7.7：列的上半部（時間、emoji、內容、列尾淡色 `ChevronRight`）是一個 `<button>`，按下只變 accent 底色；「編輯」「撤銷」那排是它的兄弟元素，不包在按鈕裡（不要巢狀按鈕，也不靠 stopPropagation）。
- 詳細頁版面以 DESIGN.md §7.7 為準；「下次」用 `DueStatus` 另起一行；不放底部主要按鈕。

## 不做
- 不改後端、不改 Sheet 欄位、不加依賴、不需要 Apps Script 重新部署。

## 測試
- 路由：`#entry/Feed/<id>` 等解析與返回；未知 table 或 id → 找不到狀態。
- describe：每種類型的詳細欄位列表；空白欄位不輸出。
- 列點擊不被「編輯」「撤銷」觸發。
- `npm test`、`npm run build` 全過。

## 驗收
1. 本機試用模式，390×844：首頁最近紀錄與紀錄頁，六種類型各點一列，都打開正確的頁面；返回後紀錄頁的篩選和捲動位置還在。
2. 列內「編輯」「撤銷」照舊，不會打開詳細。
3. 詳細頁的編輯與撤銷／復原都會正確更新列表。
4. Med 空白品項不再出現半截字；非今年的紀錄顯示年份。
5. 從 history 載入的舊列可以打開。
6. 橫向 844×390 版面正常。
