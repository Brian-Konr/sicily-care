| feed, litter, weight, med, care | `#entry/<Table>/<id>` where `<Table>` is the Sheet name: `Feed`, `Litter`, `Weight`, `Med`, `Care` (`TABLE_OF_TYPE` in `src/data/codec.ts`) |

- Edit / 撤銷 / 復原 call the same `edit` / `api.remove` / `api.restore` + toasts the timeline already uses. They work for `__pending` rows because those helpers already queue. Do not branch on `sync`.
- After 撤銷, stay on the detail page. The entry flips to `deleted` because it is read from `data.all` on each render. Title gets a strikethrough, badge 「已撤銷」, actions become only 「復原」.

## 1. `src/lib/route.ts`

Move the hash logic out of `App.tsx` so tests do not import `App`.

```ts
export const ENTRY_TABLES = ["Feed", "Litter", "Weight", "Med", "Care"] as const
export type EntryTable = (typeof ENTRY_TABLES)[number]

export type Route =
  | { name: "home" | "feed" | "litter" | "weight" | "med" | "issue" | "timeline" | "settings" | "foods" }
  | { name: "issue-detail"; id: string }
  | { name: "entry-detail"; table: EntryTable | null; id: string }

const SCREENS = ["home", "feed", "litter", "weight", "med", "issue", "timeline", "settings", "foods"] as const

export function parseHash(hash: string): Route
export function formatHash(route: Route): string  // no leading "#"
```

`parseHash` rules (apply to the string after stripping one leading `#`):

1. `issue/<id>` with non-empty `decodeURIComponent` id → `{ name: "issue-detail", id }`. Empty id falls through. This matches today’s `readHash`. A bad `%` sequence falls through to home (do not throw).
2. Exact segment `entry`, or any string starting with `entry/`, is **always** `{ name: "entry-detail", ... }`, never home.
   - Valid only when there are exactly 3 segments `entry / <table> / <id>`, `<table>` is one of `ENTRY_TABLES` (case-sensitive; `feed` and `Issue` are invalid), and decoded id is non-empty.
   - Otherwise `{ name: "entry-detail", table: null, id: "" }`. This covers missing id, extra segment, unknown table, and a bad `%`.
3. A screen name in `SCREENS` → that screen. Anything else → `{ name: "home" }`.

`formatHash`:

- issue-detail → `issue/${encodeURIComponent(id)}`
- entry-detail with a non-null table and non-empty id → `entry/${table}/${encodeURIComponent(id)}` (`Feed` needs no escaping; still fine if encoded)
- any other route → `route.name`
- Do not call `formatHash` for a not-found entry route. The app only writes hashes for rows it actually opened.

Round-trip: `parseHash("#" + formatHash(r))` equals `r` for every screen, for an issue id that contains a space, and for each of the five tables.

`App.tsx` deletes its local `Route`, `SCREENS`, `readHash`, and `writeHash`. `readHash` becomes `() => parseHash(location.hash)`. `writeHash` becomes `(r) => { location.hash = formatHash(r) }`. Keep assigning `location.hash` (pushes history). Do not use `replaceState` or `history.back()`.

`openScreen`’s argument type must exclude both `"issue-detail"` and `"entry-detail"`.

## 2. `src/lib/format.ts`

Add these two functions. Do not change `fmtWhen`, `fmtDate`, `fmtFullDate`, or `fmtDayHeader`.

`fmtEntryWhen(ts: string, now: Date): string` — move the function currently named `issueWhen` in `src/screens/IssueDetail.tsx` here unchanged:

- `dayDiff(ts, now)` in `0..6` → `fmtWhen` (`今天 18:05`, `昨天 21:10`)
- same Taipei year → `` `${fmtDate(ts)}${fmtTime(ts)}` `` which is `9/24（四）18:05` (no extra space; `fmtDate` already ends with `）`)
- other year → `` `${fmtFullDate(ts)} ${fmtTime(ts)}` `` which is `2025/12/30 18:05` (one space)

`fmtNextDue(nextDue: string): string | null`

- Accept `YYYY-MM-DD` only (`/^\d{4}-\d{2}-\d{2}$/`). Anything else, including `""`, returns `null`.
- Parse as `` `${nextDue}T12:00:00+08:00` `` so the weekday is Taipei’s.
- Return `` `${y}/${mm}/${dd}（${WEEK[wd]}）` `` with month and day zero-padded, matching the existing `parts()` helper. Example: `2026-11-09` → `2026/11/09（一）`. Always include the year. This is only for the Med 「下次」 row, not for timeline text.
