## Why this change exists

Online v1.1: an Issue photo that is a valid Drive JPEG shows the iOS broken-image icon in the detail thumb. `useIssuePhotos` treats any `getPhoto` body as ready, builds `data:${mime};base64,${data}`, puts that string in IndexedDB `sicily-photos`, and gives it to `<img>`. A bad payload is cached forever. A long data URL is also a likely iOS standalone failure even when the bytes are a real JPEG. The fix checks the payload, decodes it, caches a `Blob` in a new database, and points `<img>` at an object URL.

## 1. `src/data/photoBytes.ts`

No imports from React, the API, or the cache. Safe to unit test in Node (`atob`, `Blob`, `Uint8Array` exist; `createImageBitmap` and `Image` do not).

```ts
export type PhotoMime = 'image/jpeg' | 'image/png' | 'image/webp'
export type PhotoFailCode = 'bad_mime' | 'bad_base64' | 'bad_magic' | 'decode_failed' | 'img_error'

export type PhotoCheck =
  | { ok: true; mime: PhotoMime; bytes: Uint8Array }
  | { ok: false; code: 'bad_mime' | 'bad_base64' | 'bad_magic'; byteLength: number }

export type PhotoDecoder = (blob: Blob) => Promise<void>
```

### `normalizePhotoMime(mime: unknown): PhotoMime | null`

- If `mime` is not a string, return `null`.
- `const m = mime.trim().toLowerCase()`.
- Return `m` only when it is exactly `image/jpeg`, `image/png`, or `image/webp`.
- These are `null` (later `bad_mime`): `image/jpg`, `image/jpeg; charset=binary`, `image/png;base64`, `image/gif`, `text/plain`, `''`. Do not invent aliases.

### `decodeBase64(data: string): Uint8Array | null`

Return `null` unless all of these hold:

- `typeof data === 'string'`
- `data.length > 0`
- `data.length % 4 === 0`
- `/^[A-Za-z0-9+/]+={0,2}$/.test(data)` (no whitespace, no newlines, no `data:` prefix)
- `atob(data)` does not throw
- the decoded binary length is `> 0`

Convert with a loop: `out[i] = bin.charCodeAt(i)`. Do not use `Buffer` in `src/`. Do not strip characters before the test. A data URL string is `null`, not something to slice.

### Magic

| mime | pass condition |
|---|---|
| `image/jpeg` | length ≥ 3 and bytes `FF D8 FF` |
| `image/png` | length ≥ 4 and bytes `89 50 4E 47` |
| `image/webp` | length ≥ 12, bytes 0–3 are `52 49 46 46` (`RIFF`), bytes 8–11 are `57 45 42 50` (`WEBP`). The four size bytes at offset 4 can be anything. |

`FF D8` without the third `FF` is a fail. `RIFF` shorter than 12 bytes is a fail. `RIFF` plus `XXXX` at offset 8 is a fail. Do not require the rest of the PNG signature (`0D 0A 1A 0A`). Do not parse EXIF.

`magicMatches(bytes, mime)` returns boolean.

### `validatePhotoPayload(mime: unknown, data: unknown): PhotoCheck`

In this order, and stop at the first failure:

1. `normalizePhotoMime(mime)` is null → `{ ok: false, code: 'bad_mime', byteLength: 0 }`. Do not look at `data`.
2. `data` is not a string, or `decodeBase64` returns null → `{ ok: false, code: 'bad_base64', byteLength: 0 }`.
3. `magicMatches` is false → `{ ok: false, code: 'bad_magic', byteLength: bytes.length }`.
4. Else `{ ok: true, mime: normalized, bytes }`.

Mime and magic must agree. JPEG mime + PNG bytes is `bad_magic`, not `bad_mime`.

### Decode

```ts
export async function decodePhotoBlob(blob: Blob, decode: PhotoDecoder = defaultPhotoDecoder): Promise<void> {
  await decode(blob)
}
```

`defaultPhotoDecoder`:

- If `typeof createImageBitmap === 'function'`, `const bmp = await createImageBitmap(blob)`, call `bmp.close?.()`, return. If `createImageBitmap` rejects, the rejection propagates. Do not catch it and try `Image`.
- Else use `new Image()` and `await img.decode()`. Set `img.src` to `URL.createObjectURL(blob)`. `URL.revokeObjectURL` that temporary URL in a `finally`. This temporary URL is not the one shown in the UI.
- If `Image` or `URL.createObjectURL` is missing, throw. Tests always pass an injected decoder, so they never hit this branch.

### `warnPhoto(code: PhotoFailCode, byteLength: number): void`

```ts
console.warn('sicily-photo', code, byteLength)
```

Exactly three arguments. `byteLength` is a non-negative integer. Do not log mime, base64, bytes, `fileId`, the object URL, or the blob.

### `dataUrlByteLength(dataUrl: string): number`

Used for local pending photos. Take the substring after the first comma. Run `decodeBase64`. Return the byte length, or `0` if that fails. Do not log the string.

## 2. Cache — `src/data/photoCache.ts`

```ts
export const PHOTO_DB_NAME = 'sicily-photos-v2'
export const PHOTO_DB_PREV = 'sicily-photos'
export const PHOTO_STORE = 'photos'

export interface PhotoCache {
  get(fileId: string): Promise<{ mime: string; blob: Blob } | null>
  put(fileId: string, mime: string, blob: Blob): Promise<void>
  delete(fileId: string): Promise<void>
}

export interface PhotoCacheRow {
  fileId: string
  mime: string
  blob: Blob
  savedAt: number
}
```

Keep `evictOldest` as it is (newest `savedAt`, cap `max`).

### Memory cache

`createMemoryPhotoCache(max = 50)` stores `PhotoCacheRow`. `get` returns `{ mime, blob }` or `null`. If the row’s `blob` is not a `Blob`, delete the key and return `null`. `put(fileId, mime, blob)` stores the `Blob` reference and evicts the same way as today (sort by `savedAt`, keep `max`). `delete` removes the key. Do not store a `dataUrl` field.

### IndexedDB cache

```ts
export function createIdbPhotoCache(max = 50, factory?: IDBFactory): PhotoCache
```

- `const idb = factory ?? (typeof indexedDB === 'undefined' ? undefined : indexedDB)`.
- If `idb` is missing, return `createMemoryPhotoCache(max)`. `App.tsx` keeps calling `createIdbPhotoCache()` with no args. In the browser that uses real `indexedDB`. In Node tests that call it with no args, it is the memory cache.
- Do not open the old database. On the first operation of this instance, `indexedDB.deleteDatabase('sicily-photos')`, then open `sicily-photos-v2` at version `1`.
- Share one delete promise (`dropOnce`) created synchronously before the first `await`, so two parallel operations delete once. Further `get` / `put` / `delete` calls must not call `deleteDatabase` again.
- `deleteDatabase` always settles resolved: `onsuccess`, `onerror`, `onblocked`, and a thrown call all resolve. A blocked old database must not hang photo loading. Then open v2 anyway.
- `onupgradeneeded`: `createObjectStore('photos', { keyPath: 'fileId' })`.
- `get`: missing row → `null`. Row whose `blob` is not a `Blob` → `delete` that key and return `null`. Any thrown IDB error → `null` (same as today).
- `put`: `store.put({ fileId, mime, blob, savedAt: Date.now() })`. Then `getAll`, `evictOldest(..., max)`, delete ids that were not kept. Swallow write errors (a cache failure must not hide a photo that already decoded).
- `delete`: `store.delete(fileId)`. Swallow errors.
- Open a connection per operation, matching the current style. Close nothing special.
- One short comment on the new name: v1 cached undecoded data URLs under `sicily-photos`; opening v2 deletes that database.

There is no `dataUrl` anywhere in this file after the edit.

## 3. Loader — `src/data/photoLoad.ts`

The hook must not contain a second copy of this logic. Vitest cannot render hooks without new dependencies, so this function is the tested unit.

```ts
export type LoadPhotoResult =
  | { status: 'ready'; blob: Blob; byteLength: number }
  | { status: 'error'; byteLength: number; code?: PhotoFailCode }
  | { status: 'offline' }
  | { status: 'forbidden' }
  | { status: 'unavailable' }

export async function loadIssuePhoto(opts: {
  fileId: string
  version: number
  api: { getPhoto(fileId: string): Promise<{ mime: string; data: string }> }
  cache: PhotoCache
  skipCache?: boolean
  online?: boolean
  decode?: PhotoDecoder
  warn?: (code: PhotoFailCode, byteLength: number) => void
}): Promise<LoadPhotoResult>
```

`decode` defaults to `defaultPhotoDecoder`. `warn` defaults to `warnPhoto`. `online` defaults to `navigator.onLine !== false`. Tests pass `online`, `decode`, and `warn` explicitly.

Steps, in order:

1. If `skipCache` is not true:
   - `const hit = await cache.get(fileId)`.
   - If `hit` exists and `hit.blob instanceof Blob`:
     - `await decodePhotoBlob(hit.blob, decode)`.
     - On success return `{ status: 'ready', blob: hit.blob, byteLength: hit.blob.size }`. Do not call `api.getPhoto`. Do not call `put`.
     - On throw: `await cache.delete(fileId)`, `warn('decode_failed', hit.blob.size)`, then fall through. Do not return yet.
   - If `hit` exists but `blob` is not a `Blob`: `await cache.delete(fileId)`, then fall through. Do not warn.
2. If `!supportsV11(version)` (`version >= 2` from `src/data/codec.ts`): return `{ status: 'unavailable' }`. Do not call `getPhoto`. Do not warn. This branch also runs after a cache-hit decode failure when the script is old.
3. If `online` is false: return `{ status: 'offline' }`. Do not call `getPhoto`. Do not warn.
4. Try `await api.getPhoto(fileId)`.
   - `ServerError` whose `code === 'forbidden'` → `{ status: 'forbidden' }`. No warn, no `put`.
   - `NetworkError` while `online` is false → `{ status: 'offline' }`. No warn, no `put`.
   - Any other throw (`NetworkError` while online, other `ServerError`, unknown) → `{ status: 'error', byteLength: 0 }` with **no** `code`. No warn, no `put`. Do not relabel a timeout as `decode_failed`.
5. `const checked = validatePhotoPayload(response.mime, response.data)`.
   - If `!checked.ok`: `warn(checked.code, checked.byteLength)` and return `{ status: 'error', code: checked.code, byteLength: checked.byteLength }`. Do not `put`.
6. `const blob = new Blob([checked.bytes], { type: checked.mime })`. Use the normalized mime. Do not keep the base64 string.
7. `await decodePhotoBlob(blob, decode)`.
   - On throw: `warn('decode_failed', blob.size)` and return `{ status: 'error', code: 'decode_failed', byteLength: blob.size }`. Do not `put`. This is the truncated-JPEG case: magic can be valid while the injected decoder rejects.
8. `await cache.put(fileId, checked.mime, blob)`. `put` already swallows IDB errors. Then return `{ status: 'ready', blob, byteLength: blob.size }`.

`put` runs only after step 7 resolves. A failure never writes the cache.

## 4. `useIssuePhotos`

Keep the public options `{ issueId, photoIds, version, api, cache, storage }` and the behaviors that are not part of this bug.

```ts
export interface IssuePhotoItem {
  key: string
  fileId?: string
  status: PhotoThumbStatus
  /** Remote ready: blob: URL. Local: data URL. Absent otherwise. */
  src?: string
  byteLength?: number
}
```

Return `{ items, retry, markImgError }`.

### Object URLs

The hook is the only creator of display object URLs. Components must not call `createObjectURL`.

- A ref `Map<string, string>` from item key to object URL.
- `revoke(key)` revokes and deletes that entry if present.
- `urlFor(key, blob)` revokes the previous URL for that key, then `URL.createObjectURL(blob)`, stores it, returns it.
- Unmount effect revokes every URL and clears the map.
- The issue effect (the one that rebuilds `items`) increments a `gen` ref, revokes every URL, clears the map, and clears `inflight`, then builds the new items. A fetch that finishes after `gen` has moved must not call `setOne` and must not keep a URL it created. Create the object URL only after the `gen` check succeeds.

If `URL.createObjectURL` throws after a successful decode, `warnPhoto('decode_failed', blob.size)`, set `error`, do not leave `status: 'ready'` without a `src`.

### Remote items

Same as now: `photoIds.slice(0, 3)`, key = file id, initial status `loading`. Then, only when `supportsV11(version)`, call `fetchOne`. When the version is below 2, do not call the loader and do not call `getPhoto`. The detail screen already hides thumbs and shows `UpdateNeededNote` in that case. Leave those items `loading`.

`fetchOne(fileId, ticket, skipCache)`:

- If `inflight` has `fileId`, return.
- Add to `inflight`, `revoke(fileId)`, `setOne` to `{ status: 'loading', src: undefined }`.
- `await loadIssuePhoto({ fileId, version, api, cache, skipCache })`. Use the real decoder and `warnPhoto` (do not pass a test decoder from the hook).
- If `ticket !== gen.current`, return (the loader may already have cached a good blob; that is fine).
- `ready`: `setOne` `{ status: 'ready', src: urlFor(fileId, blob), byteLength }`. Do not set a data URL.
- `error`: `setOne` `{ status: 'error', src: undefined, byteLength }`. The loader already warned when `code` is set. Do not warn again.
- `offline` / `forbidden`: `setOne` that status and `src: undefined`.
- `unavailable`: `setOne` `{ status: 'loading', src: undefined }`.
- `finally`: remove `fileId` from `inflight`.

### Local items

Append after the remote ids, unchanged keys `local-${i}`, status `local`, `src` = the data URL from `pendingLocalPhotos`, `byteLength` = `dataUrlByteLength(src)`. Do not put local photos in `PhotoCache`. Do not convert them to blobs.

### `retry(key)`

- `local-*`: index is the number after `local-`. Read `pendingLocalPhotos(issueId, storage)` again. If that index exists, `setOne` back to `{ status: 'local', src: dataUrl, byteLength }` and clear the broken-guard for that key (below). If it does not exist, leave `error`. Do not call `getPhoto` or the cache.
- Otherwise find the item. If it has `fileId`, call `fetchOne(fileId, gen.current, true)`. `skipCache: true` means the loader does not call `cache.get`. Clear the broken-guard for that key before the fetch.

`online` event: same as now, only items with `status === 'offline'` and a `fileId`, and `skipCache` false.

### `markImgError(key)`

Called from `<img onError>`. It must be idempotent, because revoking the URL can make the still-mounted image fire `onError` again.

- A ref `Set` of keys already marked. If `key` is in the set, return.
- Find the item. If it is missing, or status is not `ready` and not `local`, return.
- Add the key to the set, `revoke(key)`, `setOne` `{ status: 'error', src: undefined, byteLength: item.byteLength ?? 0 }`.
- `void noteImgError({ fileId: item.fileId, byteLength: item.byteLength ?? 0, cache })`.
- `retry` removes the key from the set so a later failure can warn again.

Do not auto-call `getPhoto` from `markImgError`. The user taps 「再試一次」, which calls `retry`.

## 6. Edge cases

| Case | Result |
|---|---|
| `image/jpg`, gif, mime with parameters, non-string mime | `bad_mime`, byteLength 0, no `put`, warn once |
| `''`, bad alphabet, length not multiple of 4, data URL string, non-string data | `bad_base64`, byteLength 0, no `put` |
| Valid base64 whose magic is missing or does not match the mime | `bad_magic`, byteLength is the decoded length, no `put` |
| First 100 bytes of a JPEG (`FF D8 FF` plus padding) | validation ok; injected decoder throws; `decode_failed`, byteLength 100, no `put` |
| `createImageBitmap` exists and throws | do not fall back to `Image` |
| Decode of a network body succeeds, `put` fails | still `ready` (cache swallows) |
| Cache hit decodes | `ready`, no `getPhoto`, no second `put` |
| Cache hit decode throws | `delete`, warn `decode_failed` with `blob.size`, then one `getPhoto`. Network success replaces the cache. Network validation failure stays `error` and does not `put` |
| `retry` / `skipCache: true` | `cache.get` is not called; `getPhoto` is called |
| `img` `onError` on a remote photo | status `error`, URL revoked, `cache.delete(fileId)`, warn `img_error` and the stored byteLength. No automatic `getPhoto` |
| Second `onError` for the same key before a retry | no second warn and no second delete |
| Local `onError` | status `error`, warn `img_error`, no `cache.delete`. `retry` restores `local` from the outbox if that index is still there |
| `forbidden` | status `forbidden`, no photo-code warn, no `put`, no retry from the `online` event |
| Offline before fetch | status `offline`, `getPhoto` not called. `online` refetches with the cache enabled |
| `NetworkError` or other server error while online | status `error`, no `code`, no warn, no `put` |
| `version < 2` | hook does not call the loader. Loader, if called, does not call `getPhoto` |
| More than 3 ids | only the first 3, unchanged |
| Leaving the detail page or switching issue | revoke every object URL; a late response must not set state |
| Same `fileId` fetched twice overlapping | `inflight` guard, one `getPhoto` |
| Old `sicily-photos` rows | deleted with the database, never read, never copied into v2 |
| `deleteDatabase` blocked or throwing | still open v2; photo load must not hang |
| `indexedDB` missing | memory cache, still Blob in / Blob out |
| Row cap | still 50, newest `savedAt` kept |
| One bad photo in a set of three | the other two still load |
| Good JPEG from `compressImage` / mock upload | mime `image/jpeg`, body is raw base64 (not a data URL), magic `FF D8 FF`, so the normal local-trial path reaches `ready` |

Do not log the payload. Do not put a `data:` URL into a remote `<img>` or into IndexedDB.

## 7. Tests

Chinese test names, same style as `test/photoCache.test.ts`. Helpers that use `Buffer` stay in the test files.

`b64(bytes: Uint8Array)` = `Buffer.from(bytes).toString('base64')`.

Fixtures:

### `test/photoBytes.test.ts`

- JPEG, PNG, and WebP fixtures validate `ok: true` and the returned bytes equal the input.
- `IMAGE/JPEG` and `' image/jpeg '` validate ok.
- `''`, `'abc'`, `'****'`, `'data:image/jpeg;base64,/9j/'` → `bad_base64`, `byteLength === 0`.
- mime `image/gif`, `image/jpg`, `image/jpeg; charset=binary`, and a non-string mime → `bad_mime`, `byteLength === 0`, even when `data` is the JPEG fixture’s base64.
- JPEG mime + PNG bytes → `bad_magic`, `byteLength === png.length`.
- WebP mime + only four `RIFF` bytes → `bad_magic`.
- WebP mime + `RIFF` + 4 size bytes + `XXXX` → `bad_magic`.
- JPEG mime + `[0xFF, 0xD8]` (no third byte) → `bad_magic`.
